# GitHub Issues: управление предложениями

Ниже находятся два связанных Issue. Сначала выполняется backend-задача, затем frontend-задача подключается к готовому API.

---

## Issue 1

**Название**

`Add offers CRUD API and expiration filtering`

**Ответственный**

Backend-разработчик.

**Цель**

Добавить API для создания, редактирования и удаления предложений, поиск по названию и компании, а также исключение истёкших предложений из публичного каталога.

**Реализация**

- Создать в `PlusOne.Contracts/Models` модель запроса `SaveOfferRequest`.
- Добавить в `SaveOfferRequest` поля:
  - `CompanyName` — обязательная строка, максимум 120 символов;
  - `Title` — обязательная строка, максимум 160 символов;
  - `Description` — обязательная строка, максимум 1000 символов;
  - `Category` — обязательная строка, максимум 60 символов;
  - `SourceType` — значение перечисления `OfferSourceType`;
  - `SourceUrl` — обязательный абсолютный URL, максимум 500 символов;
  - `ValidUntil` — необязательная дата окончания действия;
  - `PromoCode` — необязательная строка, максимум 50 символов;
  - `RedemptionInstructions` — необязательная строка, максимум 500 символов.
- Добавить к полям Data Annotations, чтобы ASP.NET Core автоматически возвращал `400 Bad Request` при отсутствии обязательных данных, неправильном URL или превышении максимальной длины.
- Расширить `IOfferRepository` методами создания, обновления и удаления предложения.
- В `SqliteOfferRepository` реализовать сохранение `SaveOfferRequest` в сущность `Offer`. Перед сохранением убрать пробелы в начале и конце строк, а пустые необязательные строки сохранить как `null`.
- Изменить `GET /api/offers`:
  - параметр `search` должен фильтровать записи по частичному совпадению с `Title` или `CompanyName`;
  - поиск должен выполняться на стороне SQLite;
  - без параметра `includeExpired` не возвращать записи, у которых `ValidUntil` меньше текущей даты;
  - при `includeExpired=true` возвращать и активные, и истёкшие записи.
- Добавить в `OffersController` endpoint `POST /api/offers`:
  - принимает JSON, соответствующий `SaveOfferRequest`;
  - создаёт запись в SQLite;
  - возвращает `201 Created`, созданный `OfferDto` и заголовок `Location` для `GET /api/offers/{id}`.
- Добавить endpoint `PUT /api/offers/{id}`:
  - принимает полный объект `SaveOfferRequest`;
  - обновляет существующую запись;
  - возвращает `200 OK` и обновлённый `OfferDto`;
  - возвращает `404 Not Found`, если указанного `id` нет.
- Добавить endpoint `DELETE /api/offers/{id}`:
  - удаляет предложение из SQLite;
  - возвращает `204 No Content` после успешного удаления;
  - возвращает `404 Not Found`, если указанного `id` нет.
- Сохранить прежнее поведение `GET /api/offers/{id}` для получения одной записи.

**Критерии приёмки**

- Валидный `POST /api/offers` создаёт запись в `plusone.db` и возвращает `201` с присвоенным `Id`.
- Невалидный `POST` или `PUT` возвращает `400` и описание ошибок валидации.
- `PUT /api/offers/{id}` изменяет все редактируемые поля существующей записи и возвращает `200`.
- `PUT` и `DELETE` с отсутствующим идентификатором возвращают `404`.
- Успешный `DELETE /api/offers/{id}` возвращает `204`, после чего `GET /api/offers/{id}` возвращает `404`.
- `GET /api/offers?search=текст` возвращает только записи, в названии или компании которых встречается переданный текст.
- Истёкшая запись отсутствует в `GET /api/offers`, но присутствует в `GET /api/offers?includeExpired=true`.
- Предложение без срока действия считается активным и остаётся в публичной выдаче.
- Решение собирается командой `dotnet build PlusOne.sln --no-restore` без ошибок.

**Как проверить**

1. Запустить API командой:

   ```bash
   dotnet run --project src/PlusOne.Api --launch-profile http
   ```

2. Открыть `http://localhost:5147/swagger`.
3. Создать через `POST /api/offers` активное предложение и проверить код `201` и наличие `Id`.
4. Найти его через `GET /api/offers?search=<часть названия или компании>`.
5. Изменить название и промокод через `PUT /api/offers/{id}` и проверить обновлённый ответ.
6. Создать предложение с прошедшей датой `ValidUntil`. Убедиться, что обычный `GET /api/offers` его не возвращает, а запрос с `includeExpired=true` возвращает.
7. Удалить созданные записи через `DELETE /api/offers/{id}` и проверить коды `204`, затем `404` при повторном получении.

**Зависимости**

- Существующая сущность `Offer`, `PlusOneDbContext` и SQLite-репозиторий.

**Метки**

`backend`, `api`, `database`, `feature`

**Приоритет**

High

## Issue 2

**Название**

`Build admin offers management page`

**Ответственный**

Frontend-разработчик.

**Цель**

Создать страницу `/admin/offers`, на которой команда сможет искать, создавать, редактировать и удалять предложения без прямой работы с базой данных.

**Реализация**

- Создать Blazor-страницу `Pages/AdminOffers.razor` с маршрутом `/admin/offers`.
- Добавить ссылку «Управление» на страницу в основное меню.
- Расширить `OffersApiClient` методами:
  - загрузки списка с параметрами `search` и `includeExpired`;
  - отправки `POST /api/offers`;
  - отправки `PUT /api/offers/{id}`;
  - отправки `DELETE /api/offers/{id}`.
- При открытии страницы запросить `GET /api/offers?includeExpired=true`, чтобы администратор видел все записи.
- Добавить поисковую строку с подписью «Поиск», кнопкой «Найти» и кнопкой «Сбросить».
- При отправке поиска передавать введённый текст в параметре `search`. API должен искать по названию и компании.
- Добавить кнопку «Добавить предложение», открывающую форму создания.
- Форма должна содержать:
  - компанию;
  - название;
  - описание;
  - категорию;
  - тип источника;
  - ссылку на источник;
  - дату окончания действия;
  - промокод;
  - инструкцию по использованию.
- Использовать `EditForm`, `DataAnnotationsValidator`, `ValidationSummary` и сообщения рядом с полями. Не отправлять запрос, пока обязательные поля не прошли клиентскую валидацию.
- После успешного создания закрыть форму, показать сообщение «Предложение создано» и повторно загрузить список.
- Для каждой записи вывести компанию, название, описание, категорию, срок действия и промокод при его наличии.
- Если `ValidUntil` меньше текущей даты, показать метку «Срок истёк». Для остальных записей показать метку «Активно».
- Кнопка «Редактировать» должна открыть ту же форму, заранее заполненную данными выбранного предложения.
- После успешного обновления закрыть форму, показать сообщение «Предложение обновлено» и обновить список.
- При нажатии «Удалить» сначала показать встроенное подтверждение рядом с выбранной записью. Не использовать подтверждение браузера.
- После подтверждения отправить `DELETE`, показать сообщение «Предложение удалено» и убрать запись из списка.
- Реализовать отдельные состояния:
  - загрузка списка;
  - ошибка соединения с кнопкой «Повторить»;
  - пустой список;
  - отсутствие результатов поиска;
  - ошибка сохранения или удаления.
- Сделать страницу удобной на мобильном экране: поля формы и кнопки должны переходить в одну колонку, минимальная высота интерактивных элементов — 44 px.
- Поскольку авторизация ещё не реализована, явно показать на странице предупреждение, что раздел предназначен для учебного MVP и пока не защищён.

**Критерии приёмки**

- Переход на `/admin/offers` загружает активные и истёкшие предложения из API.
- Поиск по части названия или компании обновляет список, а «Сбросить» возвращает полный список.
- Форма не отправляется при пустых обязательных полях и показывает, какие поля необходимо заполнить.
- После создания новое предложение появляется в списке без ручной перезагрузки страницы.
- При редактировании форма содержит текущие значения всех полей, а после сохранения список показывает новые данные.
- Удаление невозможно одним случайным нажатием: сначала появляется подтверждение, после подтверждения запись исчезает из списка.
- Истёкшие предложения имеют заметную метку «Срок истёк».
- Ошибка API не приводит к пустому белому экрану: пользователь видит сообщение и кнопку повторной загрузки.
- Страница остаётся читаемой и управляемой при ширине экрана 390 px.
- Решение собирается командой `dotnet build PlusOne.sln --no-restore` без ошибок.

**Как проверить**

1. Запустить API и Blazor WebAssembly.
2. Открыть `http://localhost:5112/admin/offers`.
3. Найти существующее предложение по части названия, затем нажать «Сбросить».
4. Открыть форму создания, проверить сообщения при пустых обязательных полях.
5. Заполнить все поля, создать предложение и убедиться, что оно появилось в списке.
6. Нажать «Редактировать», изменить название, промокод и срок действия, сохранить и проверить новые значения.
7. Установить прошедший срок и убедиться, что в административном списке появилась метка «Срок истёк», а в публичном каталоге `/offers` эта запись отсутствует.
8. Нажать «Удалить», сначала отменить подтверждение, затем подтвердить удаление и убедиться, что запись исчезла.
9. Остановить API, обновить страницу и проверить состояние ошибки; снова запустить API и нажать «Повторить».
10. Открыть инструменты разработчика браузера, включить ширину 390 px и проверить форму, список и кнопки.
